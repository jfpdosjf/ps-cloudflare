راهنمای نصب و استفاده

پنل PasarGuard با هسته‌ی Xray روی Cloudflare. نصب یک‌بار انجام میشه و بعدش خودش بالا میاد، ساخت کانفیگ‌ها رو خودش انجام میده و از دیتابیس بکاپ می‌گیره.

در حال بررسی وضعیت…
پیش‌نیاز نصب ورود به پنل ساخت کاربر دامنه‌ی اختصاصی آپدیت و بکاپ مشکل‌ها

پیش‌نیاز

  • حساب Cloudflare با پلن Workers Paid (ماهی ۵ دلار). Containers روی پلن رایگان کار نمی‌کنه.
  • روی کامپیوترت: Node.js نسخه‌ی ۲۰ یا بالاتر، Git و Docker (Docker باید روشن باشه، wrangler باهاش ایمیج رو می‌سازه).
  • یا اگه نمی‌خوای چیزی نصب کنی: یک حساب GitHub، دیپلوی رو GitHub Actions انجام میده (روش ب پایین).

نصب

روش الف: یک دستور از کامپیوتر

  1. پروژه رو بگیر 
    git clone <آدرس-ریپوی-خودت> sepnet-cf
cd sepnet-cf
  2. اسکریپت نصب رو اجرا کن

    توکن API و Account ID رو ازت می‌پرسه. بعدش همه‌چیز خودکاره: بررسی توکن، ساخت فضای بکاپ، ساخت ایمیج، دیپلوی و چاپ آدرس و یوزر و رمز.

    ./install.sh
  3. آدرس رو باز کن

    آخر اسکریپت آدرس چیزی شبیه sepnet.<اسم-تو>.workers.dev چاپ میشه. اولین بالا اومدن تا دو دقیقه طول می‌کشه و صفحه‌ی «پنل در حال بالا اومدنه» رو می‌بینی.

روش ب: بدون نصب چیزی، با GitHub Actions

  1. ریپو رو Fork کن

    یا خودت یک ریپوی خصوصی بساز و فایل‌ها رو توش بذار.

  2. دو Secret اضافه کن

    توی Settings ← Secrets and variables ← Actions:

    اسماز کجا بیارم
    CLOUDFLARE_API_TOKENداشبورد Cloudflare ← My Profile ← API Tokens ← قالب «Edit Cloudflare Workers». دسترسی R2 هم اضافه کن.
    CLOUDFLARE_ACCOUNT_IDسمت راست صفحه‌ی Workers & Pages
  3. یک Push بزن

    یا از تب Actions دکمه‌ی Run workflow رو بزن. از این به بعد هر Push خودکار دیپلوی میشه.

ورود به پنل

یوزر و رمز مالک موقع اولین اجرا خودکار ساخته میشه و تو فضای بکاپ نگه‌داری میشه. برای دیدنش:

npm run creds

خروجی یک JSON هست؛ مقدار user و pass رو بردار. بعد برو به:

__ORIGIN__/dashboard/
رمز رو عوض کنرمز رو از داخل پنل عوض کن و فایل خروجی بالا رو جایی پخش نکن. توکن بکاپ هم داخل همون فایله.

ساخت کاربر و لینک اشتراک

  • تو پنل، Users ← Create. یکی از قالب‌های آماده (۱۰ گیگ، ۳۰ گیگ، …) رو انتخاب کن یا حجم و تاریخ رو دستی بذار.
  • گروه SEPNET خودکار وصل میشه و پنج کانفیگ (VLESS، Trojan، VMess، HTTPUpgrade) تو لینک اشتراک قرار می‌گیره.
  • لینک اشتراک رو بده به کاربر. تو برنامه‌هایی مثل v2rayNG، Hiddify یا Streisand «افزودن از لینک اشتراک» رو بزنه.

مسیر هر کانفیگ موقع نصب تصادفی ساخته میشه و بعد از ریستارت عوض نمیشه، پس لینک کاربرها سالم می‌مونه.

دامنه‌ی اختصاصی

آدرس workers.dev کار می‌کنه ولی بعضی اپراتورها فیلترش می‌کنن. اگه دامنه‌ای تو Cloudflare داری:

  1. فایل wrangler.jsonc رو باز کن

    خط‌های کامنت‌شده‌ی routes رو از کامنت دربیار و دامنه‌ات رو بنویس، مثلاً panel.example.com.

  2. دوباره دیپلوی کن 
    ./deploy.sh
  3. یک بار پنل رو با دامنه‌ی جدید باز کن

    سیستم دامنه رو از همین بازدید یاد می‌گیره، آدرس کانفیگ‌ها و لینک اشتراک رو عوض می‌کنه و کانفیگ‌های دامنه‌ی قبلی رو پاک می‌کنه.

آپدیت و بکاپ

  • بکاپ: هر دقیقه از دیتابیس و کلیدها یک نسخه تو R2 ذخیره میشه، فقط وقتی چیزی تغییر کرده باشه.
  • ریستور: هر بار کانتینر دوباره بالا بیاد (آپدیت، ریستارت، خواب) آخرین نسخه خودکار برمی‌گرده. حداکثر یک دقیقه از آخرین تغییرها ممکنه از دست بره.
  • آپدیت پنل: دوباره ./deploy.sh یا یک Push. ایمیج PasarGuard با latest ساخته میشه؛ اگه نسخه‌ی ثابت می‌خوای تگ رو تو container/Dockerfile بذار.
  • پاک کردن همه‌چیز و شروع تازه: آبجکت data.tgz رو از باکت sepnet-backup حذف کن و کانتینر رو ریستارت کن.

مشکل‌ها

علامتکاری که بکن
دیپلوی ارور instance_type میدهتو wrangler.jsonc مقدار رو بذار basic. حافظه‌ش کمتره و با کاربر زیاد کند میشه.
ارور Docker موقع دیپلویDocker Desktop رو روشن کن. روی مک M1/M2 باید ایمیج amd64 ساخته بشه، wrangler خودش حواسش هست.
صفحه‌ی «در حال بالا اومدن» بیشتر از ۵ دقیقه موندnpx wrangler tail رو اجرا کن و لاگ‌هایی که با [sepnet] یا [bootstrap] شروع میشن رو ببین.
پنل بالاست ولی کانفیگ‌ها خالیهدامنه هنوز یاد گرفته نشده. صفحه‌ی /dashboard/ رو یک بار با همون آدرس نهایی باز کن و ۳۰ ثانیه صبر کن.
اتصال کانفیگ‌ها برقرار نمیشهتو کلاینت «Fragment» یا «uTLS» رو امتحان کن و یک بار هم آدرس workers.dev رو با دامنه‌ی اختصاصی عوض کن.
قبل از استفاده‌ی جدی این رو بدون هزینه‌ی Cloudflare Containers بر اساس زمان روشن بودن و حجم مصرف حساب میشه، پس ترافیک سنگین هزینه‌ی واقعی داره. شرایط استفاده‌ی Cloudflare رو هم درباره‌ی عبور ترافیک پروکسی از Workers و Containers خودت بخون و مسئولیتش با خودته.
این صفحه فقط از Worker سرو میشه و به پنل وابسته نیست، پس حتی وقتی کانتینر خاموشه هم باز میشه.
